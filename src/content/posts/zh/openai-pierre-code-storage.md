先交代一句词：git 是管理代码版本的工具，把每一次改动记下来，改坏了能退回去；仓库是一个项目的改动账本；托管是把账本放到服务器上供大家取用的服务，GitHub 是最大的一家；agent 是能自己接活、写代码、交代码的 AI 程序；Codex 是 OpenAI 的编程 agent，它有两种模式，一种装在你自己电脑上运行，另一种在网页上派活、由 OpenAI 的服务器运行，下文分开讲。

11 月 4 日，OpenAI 宣布收购 Pierre。Pierre 的主要产品叫 Code Storage，是一个存放代码仓库的服务。收购价格没有公布，交易还要等监管批准，完成之前两家公司各自独立。

OpenAI 在公告里说了两件事：一是 Code Storage 的现有客户在交易完成后可以继续用，二是它会把 Code Storage 的功能逐步做进 Codex。还有一件事早就发生了：Codex 里浏览文件、审查改动用的两个库 Trees 和 Diffs，本来就是 Pierre 做的。

先说本地开发，因为这一部分什么都不变。你在自己电脑上做项目，仓库还是要建的：不是你自己建，就是让 agent 帮你建，建在本地；或者你在 GitHub 上先建好仓库，再复制一份到本地。Codex 装在你电脑上运行的那种模式，也就是命令行工具、桌面应用和编辑器插件，就在这个本地仓库里干活，改的是你硬盘上的文件。你不往外推送，代码就出不了你的电脑。这一层跟 Pierre 没有任何关系。

那 Code Storage 是给谁用的？它没有给人看的网页界面，它是一个供程序调用的接口。做平台的公司把这个接口嵌进自己的产品里，产品里的 agent 要新建仓库、存代码的时候，直接调用它。用它的客户是 Lovable、Bolt、Amp 这类平台：用户在网页上让 agent 生成一个应用，这个应用的代码，就存在 Code Storage 里。

这些平台为什么不直接用 GitHub？因为 GitHub 是按人用的方式设计的，登录和限流（给每个账号定的使用次数上限）都是给人准备的。平台那边的工作方式不一样：几十个 agent 同时往一个仓库里写代码，仓库还要能大到 32TB（一台普通笔记本的硬盘通常不到 1TB）。Code Storage 就是按机器的工作方式做的，它把代码存好之后，还能同步回 GitHub、GitLab 和 Bitbucket。

所以，代码在什么情况下会存到云端？就是你不用本地模式、改用云端模式的时候。拿 Codex 来说，你在网页上给它派活，它要求你先连上一个 GitHub 仓库，任务在 OpenAI 的服务器上跑，代码先复制一份到它那边，改完再把结果送回来。Lovable 这类平台也是同样的道理，你让它生成的应用，代码先存在平台那边。

本地和云端的分界就在这里。本地模式，代码在你的硬盘上，放哪、谁能看，你说了算。云端模式，代码从写出来那一刻就在别人的服务器上，存放在哪、谁能看，是平台定的。OpenAI 这次买下 Code Storage 要做进 Codex，动的正是云端这一侧：它在公告里说，想让 Codex 把从 agent 开始写代码到代码上线的整条链都管下来。这一步今天还没做完，交易也还没完成，但是方向已经摆在那里了。

我的看法是，这件事跟个人用户的关系，不在于你要不要换工具，而在于你先得分清自己在用哪种模式。本地那套照旧，仓库照建。云端那套图的是方便，可是代码也就不在你自己手里了。这一条分不清，先谈哪个 agent 好用，是没有意义的。
